# QA проєкту GREENLABS

Сайт статичний і викочується з `main` автоматично, тож помилка їде в прод без
проміжної зупинки. Дешевше знайти її тут.

## Три рівні, у порядку зростання вартості

### 1. Тести — секунди, без мережі

```bash
pnpm test
```

Що стережуть:

| Файл | Про що |
|---|---|
| `tests/phone.test.mjs` | маска телефону й перевірка імені — через неї йде кожна заявка |
| `tests/worker.test.mjs` | контракт приймача: гілки заявки й вакансії, пастка для ботів, екранування, межі |
| `tests/sheet.test.mjs` | захист клітинок від формул у коді Apps Script |
| `tests/build.test.mjs` | вміст пререндеру: сторінки, JSON-LD, canonical |

`fetch` у тестах Worker'а підмінений — ніщо не доходить ні в Telegram, ні в
таблицю. Ганяти можна скільки завгодно.

Тести на збірку самі пропускаються, поки немає `dist`.

### 2. Огляд зібраного сайту — хвилина, потрібен `dist`

```bash
pnpm build && node scripts/qa-audit.mjs
```

Проходить браузером по всіх пререндерених сторінках і шукає структурні
недоліки: розриви в рівнях заголовків, картинки без `alt` чи без розмірів,
поля без підписів, повторені `id`, посилання в нікуди.

Збірку не валить — це підказка людині. Дрібниця на одній сторінці не повинна
зупиняти викочування всього сайту.

### 3. Живі перевірки — тільки коли чіпали приймач заявок

Ніколи не слати справжню заявку в бойову групу заради перевірки. Для цього є
сухий режим:

```bash
curl -s -X POST https://greenlabs-leads.myshop-api.workers.dev \
  -H "Content-Type: application/json" \
  -H "Origin: https://greenlabs-one.vercel.app" \
  -d '{"kind":"vacancy","name":"Тест","phone":"+380671234567","position":"Садівник","dry":true}'
```

Очікувано: `{"ok":true,"dry":true}` — дані перевірені, назовні нічого не пішло.

Логи Worker'а читаються **лише через псевдотермінал** — просте перенаправлення
у файл віддає порожнечу:

```bash
script -q /dev/null npx wrangler tail --format pretty
```

Рядок `sheet 200 forbidden` означає одне: `SHEET_SECRET` у Cloudflare не
дорівнює властивості скрипта в Apps Script.

## Перед злиттям у `main`

1. `pnpm test` — усе зелене
2. `pnpm build` — у логах саме `prerender: 58 з 58 сторінок`; менше означає, що
   частина сторінок поїде порожньою для пошуковиків
3. `node scripts/qa-audit.mjs` — нових зауважень не додалось
4. Якщо чіпали `worker/` — сухий прогін і `wrangler deploy` **до** злиття,
   інакше відгуки падатимуть у список клієнтських заявок
5. Якщо чіпали `worker/sheet.gs` — в Apps Script обовʼязково
   **Розгорнути → Керувати розгортаннями → Версія: Нова версія**. Збереження на
   Диску саме по собі нічого не змінює: `/exec` віддає розгорнуту версію.
   Перевірка — відкрити `/exec` у браузері й звірити мітку версії.

## Що перевіряти руками, бо машина не побачить

- **Форма на телефоні.** Більшість людей заповнює її з телефона. Маска, підказки
  під полями, екран «Дякуємо».
- **Цифри в текстах.** Ціни, зарплати, терміни, гарантії — це обіцянки клієнту.
  Звіряти з власником, а не з попередньою версією сайту: там уже бували
  розбіжності (див. памʼять проєкту).
- **Спливні вікна.** Мають закриватись одним дотиком і не перекривати смугу
  «Зателефонувати» знизу.

## Відомі зауваження, які ще не виправлені

Знайдені оглядом 17.08.2026, усі — давніші за сторінку вакансій:

- поля `ConsultationForm` не звʼязані з підписами (`<label>` без `htmlFor`) —
  для читача з екрана форма безіменна; 54 сторінки
- три посилання `href="#"` у підвалі: Facebook, адреса, «Публічна оферта» —
  58 сторінок
- десятки картинок без `width`/`height` — сторінка стрибає при завантаженні
- розриви в рівнях заголовків на `/blog` і `/works`
