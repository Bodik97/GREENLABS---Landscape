# Приймач заявок

Маленька функція на Cloudflare Workers: приймає заявку з форми сайту й
пересилає її в Telegram.

Потрібна тому, що сайт статичний — усе, що є в його коді, публічне. Токен бота
там тримати не можна: будь-хто відкриє бандл і зможе слати повідомлення від
імені вашого бота. Тут токен лежить у секретах Cloudflare.

## Що робить

- перевіряє ім'я й телефон, відсіює порожні та явно несправжні
- ловить ботів на приховане поле-пастку: відповідає «прийнято», але нікуди не шле
- обмежує кількість заявок з однієї адреси (5 на годину), якщо підключено KV
- приймає запити лише з дозволених доменів
- екранує текст, щоб через ім'я не можна було підсунути розмітку в Telegram
- **не** відповідає успіхом, якщо Telegram повідомлення не прийняв — тоді сайт
  чесно покаже помилку з телефоном замість «дякуємо»

## Розгортання

### 1. Бот

Створює **власник бізнесу зі свого акаунта** — Telegram не дозволяє передавати
ботів між акаунтами, тож бот назавжди лишиться в того, хто його зареєстрував.

1. Написати `@BotFather`, команда `/newbot`
2. Задати назву й нік бота
3. Зберегти отриманий токен

### 2. Група

1. Створити групу, додати менеджера
2. Додати туди бота як учасника
3. Дізнатися ID групи: написати в групу будь-що і відкрити
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` — потрібне значення
   `message.chat.id`, воно від'ємне і починається з `-100`

Якщо групу створювали не з акаунта власника — передайте йому права власника
через налаштування групи. Для груп Telegram це підтримує.

### 3. Worker

```bash
cd worker
npx wrangler login
npx wrangler secret put BOT_TOKEN   # вставити токен з BotFather
npx wrangler secret put CHAT_ID     # вставити ID групи
npx wrangler deploy
```

Команда `deploy` виведе адресу вигляду
`https://greenlabs-leads.<ваш-акаунт>.workers.dev`.

### 4. Обмеження частоти (необовʼязково, але варто)

```bash
npx wrangler kv namespace create LEADS_KV
```

Отриманий `id` вписати в `wrangler.toml` і зняти коментар із блока
`[[kv_namespaces]]`, потім `npx wrangler deploy` ще раз.

Без цього кроку Worker працює, просто без захисту від напливу заявок з однієї
адреси.

### 5. Підключення сайту

У репозиторії на GitHub: **Settings → Secrets and variables → Actions →
Variables → New repository variable**

```
Name:  VITE_LEAD_ENDPOINT
Value: https://greenlabs-leads.<ваш-акаунт>.workers.dev
```

Далі будь-який пуш у `main` пересоберe сайт уже з підключеною формою.

Поки змінна порожня, форма не вдає, ніби заявку прийнято, — вона показує
помилку з номером телефону.

### 6. Після переїзду на власний домен

Дописати новий домен першим у `ALLOWED_ORIGINS` у `wrangler.toml` і виконати
`npx wrangler deploy`. Інакше браузер заблокує надсилання з нового домену.

## Перевірка

```bash
curl -X POST https://greenlabs-leads.<акаунт>.workers.dev \
  -H "Content-Type: application/json" \
  -H "Origin: https://bodik97.github.io" \
  -d '{"name":"Тест","phone":"+380671234567"}'
```

Очікувано: `{"ok":true}` і повідомлення в групі.
