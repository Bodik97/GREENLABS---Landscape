# Приймач заявок

Маленька функція на Cloudflare Workers: приймає заявку з форми сайту й
пересилає її в Telegram-групу та в Google Таблицю.

Потрібна тому, що сайт статичний — усе, що є в його коді, публічне. Токен бота
там тримати не можна: будь-хто відкриє бандл і зможе слати повідомлення від
імені вашого бота. Тут токен лежить у секретах Cloudflare.

## Що робить

- перевіряє ім'я й телефон, відсіює порожні та явно несправжні
- ловить ботів на приховане поле-пастку: відповідає «прийнято», але нікуди не шле
- обмежує кількість заявок з однієї адреси (5 на годину), якщо підключено KV
- приймає запити лише з дозволених доменів
- доводить таблиці, що запит саме від нього, спільним секретом — самої адреси
  скрипта для запису вже не досить
- екранує текст, щоб через ім'я не можна було підсунути розмітку в Telegram
- шле заявку в Telegram і в таблицю одночасно; якщо один канал недоступний,
  заявка все одно осідає в другому
- **не** відповідає успіхом, якщо заявку не прийняв жоден канал — тоді сайт
  чесно покаже помилку з телефоном замість «дякуємо»

## Розгортання

### 1. Бот

Створює **власник бізнесу зі свого акаунта** — Telegram не дозволяє передавати
ботів між акаунтами, тож бот назавжди лишиться в того, хто його зареєстрував.

1. Написати `@BotFather`, команда `/newbot`
2. Задати назву й нік бота
3. Зберегти отриманий токен

### 2. Група

1. Створити групу, додати менеджера
2. Додати туди бота як учасника
3. Дізнатися ID групи: написати в групу будь-що і відкрити
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates` — потрібне значення
   `message.chat.id`, воно від'ємне і починається з `-100`

Якщо групу створювали не з акаунта власника — передайте йому права власника
через налаштування групи. Для груп Telegram це підтримує.

### 3. Таблиця

1. Створити Google Таблицю (шапку робити не треба — перша заявка створить її сама)
2. У ній: **Розширення → Apps Script**
3. Стерти те, що в редакторі, і вставити вміст файлу `worker/sheet.gs`
4. Зберегти (дискета), назвати проєкт як завгодно
5. **Розгорнути → Новий розгортання → тип «Веб-застосунок»**, параметри:
   - *Виконувати від імені*: **Я**
   - *Хто має доступ*: **Усі**
6. Google попросить дозвіл — погодитись (на екрані «Google не перевірив цей
   застосунок» тиснути *Додатково → Перейти до …*, це ваш власний скрипт)
7. Скопіювати адресу вигляду
   `https://script.google.com/macros/s/AKfy…/exec`
8. Придумати довгий випадковий пароль — це спільний секрет із Worker'ом.
   Наприклад: `openssl rand -base64 24`
9. У редакторі Apps Script: **Налаштування проєкту** (шестерня зліва) →
   **Властивості скрипта** → *Додати властивість*
   - *Властивість*: `SHEET_SECRET`
   - *Значення*: пароль із кроку 8

Адресу `/exec` Google мусить тримати відкритою для всіх — інакше Worker до неї
не достукається. Тому сама по собі вона захистом не є: хто її дізнався, той
дописував би в таблицю з лідами що завгодно. Захищає секрет із кроку 8 —
скрипт приймає лише ті запити, що його принесли.

Поки властивості `SHEET_SECRET` немає, скрипт не приймає **нічого**: краще
мовчазна відмова, ніж мовчазний дозвіл. Заявки при цьому не гинуть — Telegram
працює незалежно.

Секрет міняється в два кроки, без нового розгортання: спершу нове значення в
Cloudflare, тоді таке саме у Властивостях скрипта. Між ними рядки в таблицю не
йдуть, тож робіть підряд.

Доступ до самих заявок дається звичайним «Поділитися» на таблиці.

### 4. Worker

```bash
cd worker
npx wrangler login
npx wrangler secret put BOT_TOKEN   # вставити токен з BotFather
npx wrangler secret put CHAT_ID     # вставити ID групи
npx wrangler secret put SHEET_URL    # вставити адресу з кроку 3
npx wrangler secret put SHEET_SECRET # той самий пароль, що у Властивостях скрипта
npx wrangler deploy
```

Таблиця необовʼязкова: без `SHEET_URL` Worker працює як раніше, тільки Telegram.

Worker уже розгорнутий за адресою
`https://greenlabs-leads.myshop-api.workers.dev`. Сховище для обмеження частоти
теж створене й підключене в `wrangler.toml`, окремих дій не потребує.

Лишається тільки покласти чотири секрети командами вище і повторити `deploy` —
без них Worker відповідає `502 delivery_failed`, бо заявку нікуди подіти.

### 5. Підключення сайту

У Vercel: проєкт `greenlabs` → **Settings → Environment Variables**

```
Name:  VITE_LEAD_ENDPOINT
Value: https://greenlabs-leads.myshop-api.workers.dev
```

Далі будь-який пуш у `main` пересоберe сайт уже з підключеною формою. Змінну
читає збірка, а не браузер, тож без нового викочування вона не застосується.

Поки змінна порожня, форма не вдає, ніби заявку прийнято, — вона показує
помилку з номером телефону.

### 6. При зміні домену сайту

Дописати новий домен першим у `ALLOWED_ORIGINS` у `wrangler.toml` і виконати
`npx wrangler deploy`. Інакше браузер заблокує надсилання з нового домену.

## Ротація секретів

Секрет, який ніколи не міняли, живе вічно — і той, хто його колись побачив
(колишній підрядник, старий скрін, переслане повідомлення), має доступ досі.

Календарна ротація «раз на 90 днів» для проєкту такого розміру не працює:
її ніхто не робить, а записаний, але невиконуваний порядок гірший за чесний.
Тому тут два правила, які реально дотримати.

**Міняти негайно, без розмов:**

- хтось, хто мав доступ, перестав з вами працювати
- секрет десь засвітився — у переписці, на скріні, в логах, у чаті з ШІ
- ви не памʼятаєте, хто ще його бачив

**Міняти раз на рік** — щоб перевірити, що порядок узагалі робочий. Ротація,
яку не пробували, ламається саме тоді, коли вона терміново потрібна.

### Що з чим повʼязане

| Секрет | Де лежить | Що буде під час заміни |
|---|---|---|
| `BOT_TOKEN` | Cloudflare | заявки не йдуть у Telegram; у таблицю йдуть |
| `SHEET_SECRET` | Cloudflare + Властивості скрипта | заявки не йдуть у таблицю; у Telegram ідуть |
| `SHEET_URL` | Cloudflare | те саме, що й `SHEET_SECRET` |
| `CHAT_ID` | Cloudflare | міняється лише разом із групою |

Заявка не губиться в жодному з випадків: Telegram і таблиця — незалежні канали,
і Worker відповідає помилкою, лише якщо не спрацювали обидва. Тому міняйте по
одному секрету за раз, а не все разом.

### Токен бота

1. `@BotFather` → `/mybots` → ваш бот → **API Token** → **Revoke current token**
2. `cd worker && npx wrangler secret put BOT_TOKEN` — вставити новий
3. `npx wrangler deploy`

Старий токен помирає одразу на кроці 1, тож між 1 і 3 Telegram мовчить.
Робіть підряд.

### Секрет таблиці

Порядок важливий: спершу той бік, що приймає, потім той, що шле.

1. `openssl rand -base64 24` — нове значення
2. Apps Script → **Налаштування проєкту → Властивості скрипта** → замінити
   `SHEET_SECRET`
3. `npx wrangler secret put SHEET_SECRET` → `npx wrangler deploy`

Між кроками 2 і 3 у `wrangler tail` буде `sheet 200 forbidden` — це очікувано.

Нового розгортання Apps Script тут **не** потрібно: властивості читаються
живими, адреса `/exec` не змінюється.

### Адреса таблиці

Потрібна, тільки якщо засвітилася сама адреса. Нове розгортання в Apps Script
(**Розгорнути → Керувати розгортаннями → Змінити → Нова версія**) дає новий
`/exec`; стару адресу треба **архівувати**, інакше вона працює далі. Далі
`npx wrangler secret put SHEET_URL` і `deploy`.

### Після будь-якої заміни

Прогнати перевірку з наступного розділу і переконатися, що заявка дійшла
**обома** каналами. Половина ротацій ламається тихо.

## Перевірка

```bash
curl -X POST https://greenlabs-leads.myshop-api.workers.dev \
  -H "Content-Type: application/json" \
  -H "Origin: https://greenlabs-one.vercel.app" \
  -d '{"name":"Тест","phone":"+380671234567"}'
```

Очікувано: `{"ok":true}`, повідомлення в групі й новий рядок у таблиці.

Якщо `{"ok":true}` прийшов, а рядка в таблиці немає — дивіться, що каже Worker:

```bash
npx wrangler tail
```

Рядок `sheet 401` або `sheet 403` майже завжди означає, що при розгортанні
скрипта вибрано не «Усі» в полі «Хто має доступ».

Рядок `sheet 200 forbidden` — секрети не збіглися: або `SHEET_SECRET` у
Cloudflare відрізняється від значення у Властивостях скрипта, або властивість
там ще не додана (крок 9). Що саме віддає розгорнутий скрипт, показує його
адреса `/exec`, відкрита в браузері: там мітка версії.
